# 语言风格指南 Tone Guide

> 内容质量优先于样式：一份 PPT 的底色是**文案**，排版只是让文案更好读。
> 生成任何 deck 前，先由向导固定「语言风格（tone）」，再按该风格撰写全部文案。
> 与向导的接法：answers.json 加 6 键 `"tone": "corporate"`（值见下表 key 列）。

## 一、六种语言风格速查

| key | 风格名 | 适用场景 | 语言特征 | 首句话术倾向 |
|---|---|---|---|---|
| `corporate` | 商务正式 | 汇报/提案/投资人 | 书面语、完整句、数据先行、结论导向 | 「本期重点/结论如下」 |
| `casual` | 轻松口语 | 内部分享/培训/社区 | 大白话、短句、提问开场、第一人称 | 「先说结论：」 |
| `tech` | 科技极客 | 技术分享/架构评审 | 术语精准、句式简洁、机制与指标并重 | 「核心机制是：」 |
| `story` | 叙事故事 | 发布会/品牌演讲 | 场景化、痛点→转折→解法、有画面感 | 「想象这样一个场景：」 |
| `persuasive` | 说服销售 | 销售 pitch/竞标 | 利益点先行、对比差异、行动号召 | 「您将获得/为什么选择我们」 |
| `academic` | 学术报告 | 论文答辩/调研 | 客观中立、分析框架、证据-结论 | 「本研究/本报告基于……」 |
| `government` | 政务公文体 | 政府/国企/党建汇报 | 严谨规范、公文语体、层次分明、措辞权威 | 「为深入贯彻落实……」 |

## 二、同一内容，六种写法（范例）

原始信息：**新版本加载速度提升 30%，内存占用下降 25%。**

| 风格 | 该页文案 |
|---|---|
| corporate | 「性能显著改善：加载提速 30%，内存占用回落 25%，为规模化部署夯实基础。」 |
| casual | 「新版本快多了！打开速度提升 30%，内存也省了 25%，日常用起来明显更顺。」 |
| tech | 「加载时延 -30%，常驻内存 -25%；关键路径上移除了 3 处冗余 IO 与 2 次全量拷贝。」 |
| story | 「过去每次打开要等 8 秒，现在 5 秒内完成——团队熬夜重写核心路径，换来了这 30%。」 |
| persuasive | 「30% 更快的加载 = 用户停留更久、流失更少；这是您今天就能上线验证的收益。」 |
| academic | 「经基准测试（n=1000），加载时间由 8.2s 降至 5.7s（-30.5%），内存峰值下降 25.1%，差异显著。」 |
| government | 「系统运行效率明显提升：页面加载时间缩短约三成，内存占用下降约四分之一，各项指标达到预期目标。」 |

## 三、风格 × 设计约束的联动

1. **正文 16pt、每页 ≤80 字**（容量精算）：口语/故事风写短句；商务/学术风用完整句但控制句数。
2. **标题 ≤12 字**：所有风格统一——标题给"结论/主题"，细节进正文字。
3. **数据引用**：corporate/academic 必须带口径或来源；casual/story 可口语化约数但不下编。
4. **结尾页**按风格匹配去向：
   - corporate/academic → 总结要点 + 后续安排
   - tech → 技术结论 + 开放问题
   - story → 金句收束（呼应开头场景）
   - persuasive → 行动号召 + 联系方式

## 四、生成时的硬约束

- 风格选定后**全程一致**：封面、目录描述、内容页、结语不混用其他风格腔调。
- 不写空洞口号（"共创美好未来"），每句话携带信息。
- 不用生僻网络词；避免中英混排拼写错误与"综上所说"式冗余。
- 逐字稿（presenter-mode）同样遵循所选风格，可更口语，但术语与数据必须与正文一致。
